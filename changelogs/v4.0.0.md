# v4.0.0 (2026-05-23)

第一个基于 `maibot_sdk` v2.x 的版本。从旧版 `src.plugin_system` 完整迁移到原生
新版 SDK，适配主程序 Host ↔ Runner 子进程 IPC 架构。

## 用户感知功能侧

### 新增
- **manifest v2** 协议支持，可被新版 Runner 加载
- **强类型配置访问**：基于 `PluginConfigBase`（pydantic）的嵌套配置模型，WebUI
  可自动生成配置表单
- **`llm_task_name` 配置项**：可指定主程序 `model_config.toml` 中预先配置的任务名
  用于日程生成（默认 `replyer`）
- **HookHandler 注入**：注入入口从 `POST_LLM` 事件改为
  `maisaka.planner.before_request` Hook，直接在 LLM 请求前修改 messages 列表，
  比 v3 时代更早介入、更可靠

### 移除
- **`custom_model` 段**：插件内置 HTTP 直连模型的配置被删除（v3 的 hack 实现
  依赖向 `src.config.api_ada_configs` 注册临时 provider，在新版子进程架构下不可行）。
  原 `custom_model` 用户请改用主程序 `model_config.toml` 任务名

### 行为变更
- **图片发送**：`/plan list` 从 v3 的 `imageurl + file://` 改为通过 `ctx.send.image`
  发送 base64，更标准、跨平台
- **组件命名**：所有 Tool / Command / EventHandler / HookHandler 内部名加 `_v4`
  后缀避免与并行运行的 v3 冲突；用户使用的命令文本（`/plan` `/规划`）保持不变

### 兼容性
- 用户的 v3 `config.toml` 大部分字段无需改动即可使用，唯一需要的修改是给
  `[plugin]` 段补一个 `config_version = "4.0.0"`
- 数据库文件 `data/goals.db` 与 v3 格式完全兼容，可直接复制迁移

## 开发侧（包含修复和插件 SDK / API 改动）

### plugin
- 完全重写 `plugin.py` 为 `MaiBotPlugin` 子类，使用 7 个组件装饰器
  （4 Tool + 1 Command + 1 EventHandler + 1 HookHandler）
- 实现 `on_load / on_unload / on_config_update` 三个生命周期回调（满足
  `plugin_loader.py:535-540` 的强契约）
- 新增 `Path(__file__).parent / "data" / "goals.db"` 路径推导，子进程可靠
- 新增 `get_config(dotted_key, default)` 适配器，桥接 v3 风格的 dotted key
  到强类型属性访问，减少业务代码改动
- 新增 `_prefetch_bot_profile()`：`on_load` 时一次性拉取 `personality / bot.nickname`
  全局配置并缓存，PromptBuilder 通过 config 字典 `bot_profile` 段读取

### services 层（新增）
- `services/tools_service.py`：4 个 Tool 的业务实现（约 530 行）
- `services/command_service.py`：`/plan` 命令分发（约 340 行）
- `services/inject_service.py`：HookHandler 注入业务（约 480 行）
- `services/cleanup_service.py`：清理 + 自动调度后台任务

### planner
- `schedule_generator.py`：`__init__` 接受 `plugin` 引用；`_call_llm` 切换到
  `await self._plugin.ctx.llm.generate(model=task_name, …)`；未注入 plugin 时
  直接抛 `LLMError`（按 CLAUDE.md「不要兜底」原则）
- `auto_scheduler.py`：LLM 调用同上切换；构造 ScheduleGenerator 时传
  `plugin=self.plugin`
- `generator/base_generator.py`：删除约 70 行 `custom_model` hack（v3 临时向
  `src.config.api_ada_configs.global_model_config` 注册 provider）；
  `get_model_config()` 简化为返回 `(task_name: str, max_tokens, temperature)` 三元组
- `generator/prompt_builder.py`：删除 `config_api.get_global_config` 运行时调用，
  改为从 config 字典 `bot_profile` 段读取（由插件层在 `on_load` 时预拉取）
- `generator/config.py`：`ScheduleGeneratorConfig` 新增 `llm_task_name`、
  `bot_profile`、`timezone` 字段

### 基础设施
- 27 个文件批量替换 `from src.common.logger import get_logger` →
  `import logging` + `logger = logging.getLogger(__name__)`
- `tools.py` 中 `ToolParamType` 导入改自 `maibot_sdk.types`
- 删除 `config_manager.py`（v3 的 config_api 薄包装，新 SDK 已被强类型 config 取代）
- 重写 `handlers/__init__.py`：不再 export 已搬走的 EventHandler 类，仅保留
  `inject/` 智能注入子模块

### 配置 schema
- `config_models.py` 新增：把 v3 的 `config_schema` 嵌套字典翻译为 `PluginConfigBase`
  4 个嵌套类（`PluginSectionConfig` / `AutonomousPlanningConfig` / `ScheduleConfig` /
  `InjectConfig`）
- 删除 `custom_model` 段，新增 `llm_task_name` 字段

### 验证 / 残留
- 所有 LLM/配置相关模块 import 通过，**0 处 `from src.*` 残留**，
  **0 处 `maibot_sdk.compat` 残留**
- 完整生命周期模拟（on_load → 后台任务启动 → 命令执行 → Hook 注入 → on_unload）
  端到端通过

### 已知限制
- 旧版 v3 时代直接修改 `message.llm_prompt` 的字符串拼接注入语义，在 v4 中改为
  「在 messages 列表里第一个 system 消息之后插入新的 system 消息」。LLM 接收的
  上下文等价，但注入内容现在以独立 system 消息形式呈现
- 主程序 `bridge_event` 在 dict → SessionMessage 转换中丢弃 `llm_prompt` 字段，
  这是 v3 注入失效的根本原因，详见 `POC_RESULT.md`
